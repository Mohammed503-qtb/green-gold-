# المرحلة 4 — التحقق الذاتي 🕵️
### اختبر كأنك المستخدم الفعلي — واجمع الأدلة قبل قول «تم»

> **القاعدة الحاكمة (مبدأ الدليل):** «يعمل» تعني: **أنا نفّذت التدفق بنفسي
> ورأيت النتيجة الصحيحة، وهذه هي الآثار الجانبية في قاعدة البيانات، وهذا السجل.**
> كل «تم» بلا ذلك = ادعاء.

---

## 4.1 اختبار دورة الحياة الكاملة عبر الـ API (قبل الواجهة!)

النمط الأسرع والأصدق: **سكربت دورة حياة** ينفّذ الرحلة كاملة بأوامر HTTP حقيقية:

```bash
# مثال لنمط السكربت (عمليات حقيقية على الخادم الفعلي):
1. GET  /api/catalog                    → تأكد: دفعات نشطة بمخزون > 0 (احفظ batchId)
2. GET  /api/checkout-data              → احفظ zoneId و methodId
3. POST /api/orders                     → { name, phone, address, items:[{batchId, qty}] }
                                        → تحقق: الكود وُلد، الإجمالي = سعر الخادم×كمية+رسوم
4. POST /api/orders/:code/payment       → { phone, methodId, proof }
                                        → تحقق: الحالة PAYMENT_SUBMITTED (وليست PAID!)
5. GET  /api/orders/:code?phone=…       → التتبع يعرض الحالة الصحيحة + التاريخ
6. POST /api/admin/orders/:id/action    → (بـ PIN المالك) verify → الحالة CONFIRMED
7. POST /api/admin/orders/:id/action    → prepare → ready → out_for_delivery
                                        → تحقق: وُلّد OTP وأُعطي للسائق فقط
8. POST /api/admin/delivery/verify-otp  → رمز صحيح → DELIVERED / رمز خاطئ → رفض
9. POST /api/reviews                    → التقييم ارتبط بالطلب المسلَّم فقط
10. POST /api/orders (إعادة)            → إعادة الطلب بضغطة تنشئ طلبًا جديدًا صحيحًا
```

### ما يجعل هذا الاختبار ذهبيًا:
- يكشف فورًا: آلة حالة مكسورة، انتقال ممنوع يعمل، حجز لا يُحرَّر، إشعار لا يُنشأ.
- **تحقق من الآثار الجانبية بعد كل خطوة** — لا الاستجابة فقط:
  ```sql
  SELECT reservedQty FROM ProductBatch WHERE id=…  -- زاد بعد الطلب؟ عاد بعد الإلغاء؟
  SELECT COUNT(*) FROM OrderStatusHistory WHERE orderId=…  -- كل انتقال سُجّل؟
  SELECT COUNT(*) FROM AuditLog WHERE …  -- الفعل الإداري أثَر؟
  ```
- **اختبر الفشل عمدًا:**
  - كمية أكبر من المتاح → رسالة «المتار 2 حزمة فقط» (لا نجاح صامت!)
  - هاتف خاطئ في التتبع → 403 «الهاتف لا يطابق»
  - إرسال الدفع مرتين → 409 «أُرسل مسبقًا»
  - PIN موظف لا يملك الصلاحية → 403
  - تكرار الرمز OTP الخاطئ → رفض دون تغيير الحالة
- **في النهاية: نظّف بيانات الاختبار** (حذف الطلبات الوهمية/إعادة المخزون) —
  قاعدة إنتاج نظيفة تُسلَّم للمستخدمين.

## 4.2 التحقق عبر المتصفح/التطبيق (Golden Path)

بعد نجاح اختبار الـ API، امشِ نفس الرحلة **عبر الواجهة** بمتصفح آلي (agent-browser):

قائمة التحقق لكل صفحة/شاشة:
- [ ] تُصيَّر فعلًا (لا شاشة بيضاء، لا حاجز خطأ، لا انهيار ترطيب/فتر)
- [ ] البيانات الحقيقية تظهر (ليست skeleton إلى الأبد)
- [ ] كل زر رئيسي: انقر → النتيجة المتوقعة (حوار/انتقال/رسالة/سلة تتحدث)
- [ ] النماذج: أرسل فارغًا → توجيه؛ أرسل صحيحًا → نجاح
- [ سجل الخادم خالٍ من أخطاء أثناء الزيارة (افحص `dev.log` بعد الجولة)
- [ ] الاستجابة عبر مقاسي العرض: هاتف + سطح مكتب
- [ ] صفحات القصير: التذييل ملتصق بالأسفل بلا فجوة؛ الطويلة يدفع التذييل طبيعيًا

> أي خلل يُكتشف هنا يُصلح **من جذره** ثم يُعاد اختبار المسار كاملًا — ليس مجرد «انظر إن ذهب التنبيه».

## 4.3 اختبر البيئة المستهدفة نفسها (لا بيئة مثالية)

المستخدم ليس على جهازك ولا شبكتك:

| شرط واقعي | كيف تختبره |
|---|---|
| شبكة ضعيفة/متقطعة | أبطئ الشبكة، اقطعها أثناء تحميل، أعد الوصل — الكاش يعرض، المزامنة تستكمل |
| جهاز قديم | حزمة armeabi + جرّب على API قديم |
| فتح أول مرة | امسح بيانات التطبيق وابدأ من الصفر — هل الرحلة واضحة بلا دليل خارجي؟ |
| تثبيت فوق نسخة قديمة | التحديث يحفظ البيانات (نفس التوقيع!) |
| دوران/اتجاه RTL | نصوص عربية لا تنكسر، أيقونات صحيحة الاتجاه |

## 4.4 دليل الاستلام (Evidence Pack)

قبل الإعلان عن الإنجاز، جهّز حزمة أدلة مرقّمة:

```
1. سجل سكربت دورة الحياة: كل خطوة بأمرها واستجابتها الفعلية (مقاطع حقيقية)
2. لقطات متصفح للمسار الذهبي (من الفتح إلى النتيجة)
3. مقاطع من سجل الخادم أثناء الجولة — خالية من الأخطاء
4. نتائج الحالات السلبية (الرفض/التعارض/الملكية) — كما تظهر للمستخدم
5. حالة قاعدة البيانات بعد التنظيف: نظيفة، المخزون معاد
6. (إن وُجد إصدار) رابط الأصول + بصمة SHA-256
```

> 🔒 القاعدة: **ما لا دليل عليه لا يُذكر في تقرير الإنجاز.** عبارة «وأيضًا يعمل كذا»
> بلا دليل = تضخيم سيكشفه المستخدم لاحقًا ويدفع ثمنه الثقة.

---

## 4.5 معيار إنهاء هذه المرحلة (Definition of Done)

- [ ] سكربت دورة الحياة نجح كاملًا من أول مرة (أو بعد إصلاح جذري موثق)
- [ ] الحالات السلبية الخمس+ اختُبرت برسائل صحيحة
- [ ] الآثار الجانبية تحققت في القاعدة (سجلات/مخزون/إشعارات)
- [ ] المسار الذهبي عبر الواجهة مأكول بالكامل بلقطات
- [ ] بيئة ضعيفة: عمل بلا إنترنت للقراءة + فشل سريع + مزامنة
- [ ] قاعدة البيانات نظيفة من آثار الاختبار
- [ ] سجل الخادم نظيف من أخطاء الجولة

> عند هذا الحق يمكنك قول: «التدفق الكامل يعمل» — **بتعريف قابل للدفاع.**
