# 📋 قائمة الإبحار النهائية — هل المشروع جاهز فعلًا؟

> **طريقة الاستخدام (للمستخدم):** أعطِ هذه القائمة للذكاء الاصطناعي مع أي مشروع
> وقل: «لا تسلّم قبل اجتياز كل بند بدليل». أي بند بلا دليل = **غير مجتاز**.
>
> **طريقة الاستخدام (للذكاء الاصطناعي):** قبل كل «تم»، مرّ على القسم المطابق
> وأرفق الدليل مع كل مربع.

---

## 🔧 القسم A — الفهم (قبل أول سطر كود)

- [ ] قرأت الخطة بثلاث قبعات (المالك / المستخدم / المُخادِع)
- [ ] قائمة الكيانات كاملة **بما فيها**: تاريخ الحالات، سجل التدقيق، حركات المخزون، الإشعارات، الإعدادات
- [ ] قواعد العمل بصيغ قابلة للتنفيذ (من/متى/أثر/مانع)
- [ ] آلة الحالة الرئيسية مرسومة: كل حالة لها مخارج وكل مسدود له علاج
- [ ] أسئلة الحسم حُلّت أو اتُّخذ قرار مُعلَّن بديل
- [ ] وثيقة فهم أُرسلت وصُودق عليها

## 📐 القسم B — التصميم والعقود

- [ ] مخطط بيانات واحد مصدر الحقيقة — يجتوب «أسئلة المحاسب» كلها
- [ ] ملف عقود واحد: الحالات + الانتقالات (دور×فعل) + الثوابت المشتركة
- [ ] مرايا العقود في كل العملاء مطابقة (تعليق مرجعي متبادل)
- [ ] قائمة نقاط API: مسار/دور/مدخلات/أخطاء متوقعة
- [ ] جدول تهديدات → قرارات أمان موثقة (ملكية، أسعار، صلاحيات)
- [ ] القرارات المعمارية الكبرى مكتوبة **مع تبريرها**
- [ ] التجميد (Snapshot) محسوم: بيانات الفواتير/الطلبات لا تتأثر بتغيّر المصدر لاحقًا

## 🔨 القسم C — التنفيذ بلا فجوات

- [ ] الرحلة الرئيسية للمستخدم كاملة: أول نقرة → نتيجة نهائية مرئية
- [ ] كل شاشة: حالاتها الأربع (تحميل/فارغ/خطأ/نجاح) + زر تقدم ظاهر دائمًا + مخرج
- [ ] **لا شاشة بلا زر متابعة، ولا حالة آلة يصلها الطلب ولا يخرج منها المستخدم**
- [ ] الأسعار والحسابات من الخادم فقط — لا يُرسل العميل أي رقم مالي
- [ ] كل تحويل حالة عبر آلة العقود: دور مسموح + أثر جانبي (سجل/إشعار/مخزون)
- [ ] كل فعل إداري حساس: تحقق صلاحية + AuditLog
- [ ] رسائل الأخطاء بلغة المستخدم وقابلة للعرض كما هي
- [ ] (بيئة ضعيفة) كاش قراءة + مهلات قصيرة + عمل أساسي بلا إنترنت
- [ ] بذرة بيانات تغطي كل الحالات والأدوار والحدود (نفد/منخفض/وفير)

## 🕵️ القسم D — التحقق الذاتي

- [ ] سكربت دورة حياة كامل عبر API: إنشاء → دفع → تحقق → تجهيز → توصيل → تسليم (OTP) → تقييم → إعادة
- [ ] الحالات السلبية: كمية فائضة / ملكية خاطئة / تكرار دفع / صلاحية ناقصة / رمز OTP خاطئ
- [ ] الآثار الجانبية فُحصت في القاعدة (مخزون يعود، سجلات تكتمل، إشعارات تولد)
- [ ] المسار الذهبي عبر الواجهة بلقطات متصفح — لا شاشة بيضاء ولا فشل تحميل
- [ ] سجل الخادم نظيف أثناء الجولة
- [ ] اختبار أول فتح من صفر (بيانات ممسوحة) — رحلة مفهومة بلا دليل خارجي
- [ ] بيانات الاختبار نُظّفت والقاعدة سُلّمت نظيفة

## 🚀 القسم E — الإنتاج والإصدار

- [ ] خط CI ببوابات على **الحزمة النهائية**: صلاحيات/نقطة دخول/إعدادات مضمّنة/توقيع
- [ ] كل عطل تاريخي مقفول ببوابة دائمة
- [ ] أصول مسماة لكل جمهور + `checksums.txt` + جدول «أي ملف أنزّل؟»
- [ ] رقم الإصدار مرفوع، التوقيع نفسه السابق (تحديث فوق التثبيت)
- [ ] الخادم الحي يجيب عبر الرابط العام (نقاط حية + دورة مصغرة + تنظيف)
- [ ] **الأصل المنشور نُزّل وفُكّ ولمس بيديك**: البصمة مطابقة، الإعداد داخل المكتبة المترجمة
- [ ] ملاحظات الإصدار بلغة المستخدم لا بلغة المطور

## 🎓 القسم F — الانضباط والاستمرارية

- [ ] سجل عمل حي: القسم الأخير يغطي آخر مهمة بتفاصيلها وأدلتها
- [ ] أي عمل متوازٍ: كل وكيل قرأ السجل وأضاف قسمه بمعرفه
- [ ] التقرير النهائي: كل ادعاء «يعمل» مرفق بدليله أو مصنّف «غير مُتحقَّق» بصراحة
- [ ] العيوب المعروفة والمتبقية **مكتوبة بلا تجميل** مع خطة التالية

---

## ⛵ حكم الإبحار النهائي (Ship / No-Ship)

**أبحر فقط إذا:** A+B+C+D+E كلها خضراء بدليل، وF موثقة.

**المسماح الوحيد بالتأخير في التسليم (وليس بالتدليس):**
أن تقول بصراحة: «بند X غير مكتمل لأن Y — خطة إتمامه Z».

> المستخدم يغفر النقص المُعلَن؛ **لا يغفر الكذب المكتشف.**
